### 词表数据从哪来（这一节最重要）

**不放真题。词表和释义都取自 ECDICT**（开源英汉词典数据库，MIT 许可，
https://github.com/skywind3000/ECDICT），脚本只做筛选、去重、排序，**不改写任何释义**：

| 字段 | 意思 |
| --- | --- |
| `tag` 含 `cet4` | 四级大纲词汇（ECDICT 里这样的词条有 3849 行，去重后 **3846 个词**）|
| `zh` | ECDICT 的中文释义原文 |
| `f` / `b` | 当代语料库 / BNC 的词频顺序，**数字越小越高频** |
| `c` / `ox` | 柯林斯星级 / 牛津三千核心词 |

**主干词 = 这些词里词频最高的 1500 个**（规划书第十一节：一天扫 500 个，三天扫完），
**叶子词 = 剩下的 2346 个**（低频、生僻，看一眼就过）。

重新生成（会把两个 data 文件覆盖重写）：

### 每天该背多少，是怎么算的

写在 `assets/plan.js` 里，页面上也会原样显示，方便核对：

1. 考试日期 2026-12-12 上午 9:00 → 剩余天数；
2. 扣掉还没扫完的摸底天数（一天算 500 个）；
3. 再扣掉考前 14 天（规划书：写作翻译和真题音频留到最后两周）→ 剩下的是背词天数；
4. `不认识的词数 ÷ 背词天数`，向上取整到 5 的倍数 = 每天新词数；
5. 同时给出四档（10 / 20 / 25 / 30）各自要多少天、来不来得及，并标出推荐的落点。

如果算出来超过充足档的 30 个，页面会直接说要取舍，不硬扛。

### 间隔重复怎么排（阶段 2 的核心规则）

规则写在 `assets/srs.js`，**刻意做得能一眼看懂**，不搞 SM-2 那种玄学：

```
盒号 → 下次见面：1 → 1 天    2 → 3 天    3 → 7 天    4 → 16 天    5 → 35 天

选对   → 盒号 +1（封顶 5），按新盒号的间隔再来
选错   → 打回盒 1，明天再见，进错词本
```

- **新词从哪来**：摸底标「不认识」、而且还没进过卡片的词，按词频顺序取，数量由档位决定。
  摸底标「认识」的词永远不进背词流程 —— 你说你认识，就不折腾你。
- **每日新词额度会收缩到剩余词数**：比如还剩 3 个没学，今天的目标就是 3 个而不是 15 个；
  背完后额度归 0，今日页不再要求新词，当天仍能算完成、连续天数不断。
- **复习从哪来**：所有 `due <= 今天` 的词，先排盒号小的（最不熟的），再排拖得最久的。
  档位给一个复习上限，超出的部分明天再说 —— 断档攒下来的债不会一次性砸给你。
- **新词是看单词选中文，复习是看中文选单词**（都是四选一）。同一个词从两个方向各过一遍，
  比只看一遍释义牢；选项由「单词 + 日期 + 模式」做种子从主干词里抽，重绘不会换位置。
  干扰项优先同词性、词频相近；释义第一条相同或中文有连续两字重合的不入选
  （effect / result 这种不能两个都算对）。
  卡片上的释义只留第一个词性段、最多三个义项（删的是 `[计]` 这类标注和多余义项，不改写原文）。
- **单词能点读**：卡片上的「▶ 读这个词」用浏览器 TTS 现场发音，不依赖音频文件；
  复习卡片要答完才出现，免得把答案念出来。词表和错词本里的单词也能点读。
- **错词本是自愈的**：进 = 任何一次选错；出 = **连着两次选对**。
  不需要手动删，所以进度页没有删除按钮。
- **选错的词当轮末尾再问一遍**（同一轮最多重排一次），避免它就这么滑过去，也不会死循环。

### 四档：档位只决定「今天做多少」

档位和数字都在 `assets/plan.js` 的 `MODES` 里，`reviewCap` 是每天的复习上限：

| 档位 | 每天新词 | 复习上限 | 合计时间 |
| --- | --- | --- | --- |
| 只有 10 分钟 | 10 | 15 | 10 分钟 |
| 保底 | 15 | 40 | 30 分钟 |
| 标准 | 20 | 55 | 80 分钟 |
| 充足 | 25 | 70 | 100 分钟 |

默认档位 = 摸底推出来的推荐量落进哪一档（推荐 10 → 「只有 10 分钟」档）。
用户点了哪一档会存进 `settings.tier`，并记在当天记录里。

**两个数字是从规划书推出来的**：规划书写「单词 25 分钟对应大约 20 个新词 + 50–60 个复习词」，
所以标准档 = 20 新词 + 55 复习，保底和充足按单词时长（20 / 25 / 30 分钟）等比缩。
这条改动同时也改了摸底结果页的四档对照表（10 / 15 / 20 / 25）。

### 数据形状（阶段 2 新增的两个键）

```js
srs: {
  "abandon": { box: 2, due: "2026-10-14", seen: 3, ok: 2, wrong: 1, streakOk: 1, inBook: false, first, last }
},
days: {
  "2026-10-11": { tier: "std", newGoal: 20, newDone: 20, reviewGoal: 30, reviewDone: 30, done: true, ms: 900000 }
}
```

- `srs` 的键是单词本身（和摸底一样），所以词表加词、换顺序都不会串。
- 一天算「完成」= 新词到量 **且** 复习到量；`done` 由 `A.applyGoals()` 每次渲染时重算。
- 连续天数从 `days` 里 `done === true` 的日期算；今天还没做完**不算断**（从昨天往回数）。
- `ms` 是当天实际花掉的时间（每次进背词页记一次），不是估算。

### 精听（阶段 3）怎么设计的

**材料是本站自己写的**（`data/listening.js`，9 篇 88 句，手写、不是生成的，也不是真题）：

| 类型 | 篇数 | 对应四级听力 | 分值 |
| --- | --- | --- | --- |
| `passage` 听力篇章 | 3 | C 部分，10 题 | **142 分（占一半以上，所以放了三篇）** |
| `conversation` 长对话 | 3 | B 部分，8 题 | 56.8 分 |
| `news` 短篇新闻 | 3 | A 部分，7 题 | 49.7 分 |

每篇都有 `gist`（一句中文大意，盲听后对答案用）、`focus`（这一段在练什么）、
`tips`（跟读提示：哪几个词会连读、弱读）。

**朗读用 Web Speech API**（`assets/tts.js`），零音频文件、零版权风险。
两个真实现状兜住了：

- **没有语音引擎的浏览器**（headless Chrome、部分安卓）：`getVoices()` 空数组、`speak()` 不出声也不回调。
  所以每次朗读都挂了一个**按词数估算的看门狗**，到点当作读完，页面不会卡在「正在播放…」。
- **iOS Safari** 要求用户手势才能出声，所以所有播放都是按钮触发的，没有自动播放。

**听写对照**（`assets/diff.js`）用最长公共子序列对齐，不是按位置硬比：
少写一个词不会把后面整句判错。标点大小写不算错（听写练的是耳朵，不是标点）。
**虚词（a / the / of / is 这类）单独列出来，不进统计** —— 漏掉虚词和「这个单词不认识」
是两回事，混在一起会把进度数字搞脏。

**分类的结果存成 `listen.clips[id].words = { word: "recog" | "unknown" }`**，
全站累计从这份数据现算（`A.listenTally()`），不另存一份，免得两处对不上。
进度页显示的是「认识但没听出来」占的比例，**不显示听写正确率**。

**第二天重听**：做完一篇 → `due = 明天`；重听时点「听懂了（八成以上）」→ `due = 4 天后`，
点「还不行」→ `due = 明天`。重听也算当天的精听。

### 短读（阶段 4）怎么设计的

**材料也是手写的**：`data/readings.js`，6 篇，每篇 100–150 词（合计 750 词），
2–3 段，带 `topic` / `level` / `gist`（一句中文说明）/ `words`（标注的生词）。

三条硬约束写进了 `scripts/check-data.mjs`，违反就报错：

1. **每篇正文必须在 100–150 词之间**（规划书就是这么写的，脚本数出来把关）；
2. **标注的生词必须真的出现在正文里**（标了一个正文里没有的词，页面上就是个点不开的坑）；
3. **标注的生词必须在四级词表里查得到释义** —— 因为释义一律取自 ECDICT，不自己编。
   这条最实用：一开始我标了 `migration` / `sidewalk` / `caffeine`，脚本告诉我这三个词
   不在四级词表里，于是换成了 `circle` / `pavement` / `drug`。

**「加进错词本」是打通的**：短读标出的生词一定在词表里，所以点一下就写进 `srs`
（`seen=1`、`box=1`、`due=明天`、`inBook=true`、`src="reading"`）——
它和背词用同一套盒号往前走，不是另起一个生词本。这是规划书第二节那句
「不另起一套和你生活无关的背单词任务，而是把你在读的东西变成学习材料」的落地。

**中文说明读完再给**，和精听的「对一下大意」一个道理：先看说明再读，等于把答案先摊开。

### 已知的口径和取舍（下个会话别重新推翻）

- **只有主干词进了摸底**。叶子词不扫、不背（规划书：叶子词看一眼就过）。
- **摸底顺序是固定种子打乱的**（`assets/probe.js` 里的 `SEED`）。不按字母、也不按词频，
  免得第一组全是简单词、最后一天全是硬骨头。种子不能随便改，改了断点就对不上了。
- **判断存在 `localStorage` 的 `cet4.v1`**，键是单词本身，不是下标 —— 词表以后加词、
  重排都不影响已经扫过的判断。**清除浏览器数据会连进度一起清掉**，所以说明页里放了导出 / 导入。
- **主干词按词频切，是规划书的定义**（高频核心）。所以它前面那些词（government、system…）
  你多半都认识，扫起来很快；真正的信息量在中间那几百个。如果扫完发现不认识的很少，
  那是好消息，页面会直接告诉你「别在单词上耗时间，去练精听」。
- **叶子词不是「没用」，是「不背」**。做题遇到再回来查，词表页能搜。
- **背词只背「摸底标不认识」的主干词**。认识的词不进流程，叶子词不进流程 ——
  这是「不另起一套和你生活无关的背单词任务」那条设计原则的落地。
- **「只有 10 分钟」档是台阶，不是默认值**。它带着 15 个复习上限，
  因为复习断了间隔重复就废了 —— 这一档可以少，但不能没有复习。
- **词表页还没有「错词本」筛选**（错词本在进度页里）。想做的话是加一个 chip 的事，
  但没必要重复两个入口。
- **精听材料是手写的，不是生成的。** 加新材料的门槛就是往 `data/listening.js` 里写一段
  150–200 词的英文 + 一句中文大意 + 2–4 条跟读提示。写的时候刻意用四级常见词、
  自然的连读弱读、数字和时间。**别写成书面语** —— 朗读出来会像念课文。
- **精听里标「压根不认识」的词只进「听力生词」列表，不进背词错词本。** 原因：
  背词那套每个词都有盒号、due、连续答对计数，而这些词不一定在主干词表里
  （`srs` 的键必须是词表里的词，否则背词页取不到释义）。要打通的话，
  得先把生词补进词表或改成「任意词表」—— 那是另一件事，先不做。
- **真题音频只做打卡，不托管任何音频文件。** 规划书第四节第 5 条写死的。
- **ECDICT 的翻译里把换行写成了字面量 `\n`（两个字符，不是真换行）。**
  `scripts/fetch-words.mjs` 已经把这种字面量还原成真换行再按行合并 ——
  不改的话界面上会原样显示出一个 `\n`。以后再加词典源要注意这一点。
- **短读的正文里尽量不要用破折号 `—`**（检查脚本会提醒）：中英混排时容易被当成断句，
  而且 TTS 读出来会停顿，影响语感。
